# Результати виконання практичної роботи № 10

## Тема

**Комунікація у реальному часі та система нотифікацій**

## Мета роботи

Метою практичної роботи є набуття практичних навичок організації двостороннього зв'язку між клієнтом і сервером за
допомогою WebSockets та Socket.IO, роботи з кімнатами, широкомовленням і потоковою передачею даних через Server-Sent
Events. Також необхідно було ознайомитися з відправкою HTML-листів за допомогою Nodemailer та локального SMTP-сервера
Mailpit.

## Індивідуальний варіант

**Варіант 3 — одяг та взуття.**

Для предметної області обрано інтернет-магазин одягу та взуття. Кімната для підписки має формат `drop_<collectionId>`,
WebSocket-подія — `dropStarted`, а Email-нотифікація повідомляє про початок продажу нової сезонної колекції.

## Завдання роботи

У межах практичної роботи розроблено серверний застосунок на NestJS та клієнтську HTML-сторінку для перевірки обміну
повідомленнями. Реалізовано три рівні:

1. WebSocket Gateway, події ping/pong і глобальне широкомовлення.
2. Персоналізовані кімнати Socket.IO та SSE-потік системних показників.
3. Відправку HTML-листів через Nodemailer і Mailpit та спільний сценарій WebSocket + Email.

# 3. Рівень 1 — налаштування WebSocket Gateway

Для організації двостороннього зв'язку створено клас `EventsGateway`.

Він використовує декоратор `@WebSocketGateway()` та дозволяє CORS-запити:

```typescript
@WebSocketGateway({
    cors: {origin: '*'},
})
```

Клас реалізує інтерфейси `OnGatewayConnection` та `OnGatewayDisconnect`.

Під час підключення клієнта виконується метод `handleConnection()`, який фіксує його ідентифікатор `socket.id` та
збільшує кількість активних з'єднань.

Під час відключення викликається `handleDisconnect()`, який зменшує лічильник активних підключень.

## 3.1. Обробка ping та pong

Для перевірки активності з'єднання реалізовано подію `ping`.

Клієнт надсилає:

```javascript
socket.emit('ping');
```

Сервер повертає подію `pong` із поточним часом:

```typescript
client.emit('pong', {
    timestamp: new Date().toISOString(),
    message: 'З’єднання активне',
});
```

Таким чином можна перевірити, що клієнт і сервер обмінюються повідомленнями через WebSocket.

## 3.2. Глобальне широкомовлення

Для відправки повідомлень усім підключеним клієнтам реалізовано подію `broadcastNotification`.

Сервер формує об'єкт із текстом повідомлення, ідентифікатором відправника та часом відправки.

Для трансляції використовується:

```typescript
this.server.emit('globalAlert', payload);
```

Усі активні клієнти, які підключені до сервера, отримують подію `globalAlert`.

## 3.3. Клієнтський інтерфейс

Створено файл `public/client.html`, який підключає бібліотеку Socket.IO Client.

Інтерфейс дозволяє:

- перевіряти підключення до сервера;
- надсилати `ping`;
- отримувати `pong`;
- надсилати глобальні повідомлення;
- переглядати повідомлення, отримані від сервера.

Для перевірки широкомовлення можна відкрити сторінку у двох вкладках браузера. Повідомлення, надіслане з однієї вкладки,
відображається в обох.

# 4. Рівень 2 — робота з кімнатами Socket.IO

Для предметної області варіанта 3 використовується формат кімнати:

```text
drop_<collectionId>
```

Наприклад:

```text
drop_101
```

## 4.1. Приєднання до кімнати

Для підписки клієнта реалізовано подію `joinRoom`.

Після отримання ідентифікатора кімнати сервер викликає:

```typescript
await client.join(roomId);
```

Після успішного приєднання клієнту надсилається підтвердження `joinedRoom`.

## 4.2. Вихід із кімнати

Для виходу використовується подія `leaveRoom`:

```typescript
await client.leave(roomId);
```

Після цього клієнт більше не отримує повідомлення, адресовані цій кімнаті.

## 4.3. Адресне надсилання повідомлень

Для відправки подій конкретній групі підписників створено метод:

```typescript
emitToRoom(roomId
:
string, event
:
string, data
:
unknown
):
void {
    this.server.to(roomId).emit(event, data);
}
```

Таким чином повідомлення отримують тільки клієнти, які приєдналися до відповідної кімнати.

У межах індивідуального варіанта для запуску продажу колекції використовується подія `dropStarted`.

# 5. Реалізація Server-Sent Events

Для потокової передачі системних показників створено `NotificationsController`.

Ендпоінт:

```text
GET /notifications/events/stream
```

Для реалізації використано декоратор `@Sse()` та реактивний потік `Observable`.

```typescript
@Sse('events/stream')
streamEvents()
:
Observable < MessageEvent > {
    return interval(5000).pipe(
        map((tick) => ({
            type: 'systemUpdate',
            data: {
                status: 'online',
                activeConnections: this.eventsGateway.getActiveConnections(),
                serverTime: new Date().toISOString(),
                tick: tick + 1,
            },
        })),
    );
}
```

Оновлення генеруються кожні п'ять секунд.

Кожне повідомлення містить:

- поточний стан сервера;
- кількість активних WebSocket-з'єднань;
- поточний час сервера;
- порядковий номер оновлення.

На клієнтській стороні використовується вбудований браузерний клас `EventSource`.

Отримані повідомлення автоматично додаються до відповідного списку на сторінці.

# 6. Рівень 3 — налаштування Mailpit

Для тестування електронної пошти додано файл `docker-compose.yml`.

У ньому описано сервіс Mailpit із двома відкритими портами:

```yaml
services:
  mailpit:
    image: axllent/mailpit:latest
    container_name: webpractice10-mailpit
    restart: unless-stopped
    ports:
      - "1025:1025"
      - "8025:8025"
```

Порт `1025` використовується для SMTP-з'єднання, а `8025` — для вебінтерфейсу Mailpit.

Запуск контейнера виконується командою:

```bash
docker compose up -d
```

Вебінтерфейс доступний за адресою:

```text
http://localhost:8025
```

Mailpit перехоплює листи та дозволяє переглядати їх без фактичної відправки зовнішнім адресатам.

# 7. Реалізація MailService

Для роботи з електронною поштою створено сервіс `MailService`.

Він використовує бібліотеку `nodemailer` та створює SMTP-транспорт:

```typescript
this.transporter = nodemailer.createTransport({
    host: process.env.SMTP_HOST || 'localhost',
    port: Number(process.env.SMTP_PORT) || 1025,
    secure: false,
    ignoreTLS: true,
});
```

Для відправки листів реалізовано метод:

```typescript
async
sendNotificationEmail(
    to
:
string,
    subject
:
string,
    htmlContent
:
string,
):
Promise<string>
```

Метод приймає адресу отримувача, тему та HTML-вміст листа.

## 7.1. HTML-шаблон листа

Для варіанта 3 створено HTML-шаблон повідомлення про початок продажу нової сезонної колекції.

Шаблон містить:

- назву магазину;
- заголовок про початок продажу;
- назву сезонної колекції;
- ідентифікатор колекції;
- поточний статус;
- кнопку переходу до клієнтського інтерфейсу;
- інформацію про автоматичне формування листа.

Для кращого відображення на різних пристроях використано табличну структуру та адаптивні параметри ширини.

Також значення, які вставляються в HTML, проходять екранування, щоб уникнути некоректної інтерпретації HTML-символів.

# 8. Комплексний бізнес-сценарій

Для демонстрації спільної роботи WebSocket та Email реалізовано REST-ендпоінт:

```text
POST /collections/:id/start
```

Приклад запиту:

```json
{
  "customerEmail": "customer@example.com",
  "collectionName": "Autumn / Winter 2026"
}
```

Для запуску сценарію клієнт передає ідентифікатор колекції, адресу електронної пошти та назву колекції.

У `CollectionsService` виконуються такі дії:

1. Формується назва кімнати `drop_<collectionId>`.
2. Створюється об'єкт повідомлення про початок продажу.
3. Через `EventsGateway.emitToRoom()` надсилається подія `dropStarted`.
4. Формується HTML-лист.
5. Через `MailService.sendNotificationEmail()` лист передається SMTP-серверу Mailpit.

Таким чином клієнти, які підписані на відповідну кімнату, отримують повідомлення в реальному часі, а покупець додатково
отримує Email-нотифікацію.

Відповідь REST API містить результат виконання операції, назву кімнати, назву події та ідентифікатор сформованого листа.

Важливо: якщо SMTP-сервер недоступний, WebSocket-подія вже могла бути відправлена. У такому випадку HTTP-запит
завершується помилкою, а проблема SMTP не приховується.

# 9. Перевірка роботи програми

Для запуску проєкту необхідно встановити залежності:

```bash
npm install
```

Після цього запустити Mailpit:

```bash
docker compose up -d
```

Запуск NestJS у режимі розробки:

```bash
npm run start:dev
```

Клієнтський інтерфейс відкривається за адресою:

```text
http://localhost:3000/client.html
```

Для перевірки необхідно відкрити сторінку у двох вкладках браузера, приєднати обидва клієнти до кімнати `drop_101` та
надіслати глобальне повідомлення.

Після запуску продажу колекції через інтерфейс потрібно перевірити отримання події `dropStarted` та наявність листа у
Mailpit.

Також можна перевірити збірку проєкту:

```bash
npm run build
```

# Висновок

У ході виконання практичної роботи було розроблено систему нотифікацій для інтернет-магазину одягу та взуття на базі
NestJS.
На першому рівні було реалізовано WebSocket Gateway із використанням Socket.IO. Додано обробку підключення та
відключення клієнтів, перевірку з'єднання через `ping` і `pong`, а також глобальне надсилання повідомлень за допомогою
механізму Broadcasting.
На другому рівні було реалізовано кімнати Socket.IO для окремих сезонних колекцій. Це дозволяє надсилати повідомлення
лише клієнтам, які підписані на відповідну колекцію. Також було створено SSE-ендпоінт, який кожні п'ять секунд передає
системні показники сервера за допомогою RxJS.
На третьому рівні було інтегровано Nodemailer та Mailpit для тестування електронних листів. Створено HTML-шаблон
повідомлення про початок продажу сезонної колекції та REST-ендпоінт, який запускає комплексний сценарій сповіщення через
WebSocket і Email.
У результаті роботи було закріплено навички створення систем реального часу, роботи з асинхронними подіями, потоковою
передачею даних та інтеграції поштових сервісів у NestJS.
